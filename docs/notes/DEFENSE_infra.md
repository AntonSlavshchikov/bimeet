# Защита: инфраструктура Bimeet

Шпаргалка для устного ответа. Источник фактов — `master`
(PR #7 влит, `efcebc2`): `docs/adr/`, `docs/architecture.md`, `infra/terraform/README.md`.

---

## 1. Рассказ на 3–5 минут

**1. Что развёрнуто (30 с).** Весь продукт — один `docker-compose`: Traefik,
лендинг, фронтенд, Go-backend, Postgres и MinIO. Всё на одной ВМ Timeweb Cloud
в Москве: 1 CPU, 2 ГБ, 15 ГБ NVMe. Показать схему 1 из `architecture.md`.

**2. Инфраструктура как код (40 с).** Сервер описан в Terraform: проект,
SSH-ключ, публичный IP, сервер, облачный файрвол с семью правилами — 12
ресурсов. `terraform plan` против реального API прошёл. cloud-init при первой
загрузке ставит Docker, ufw, fail2ban, отключает вход по паролю и root.
Деталь, которую стоит упомянуть: IP создаётся *до* сервера, иначе cloud-init
остался бы без интернета.

**3. Выбор провайдера (60 с).** Драйверы: данные в РФ (242-ФЗ), Terraform,
цена, Москва. Сравнивали три (ADR 0001):
- Yandex Cloud: в октябре 2026 дроны вывели из строя три их ДЦ, сам Yandex
  объявил «аварийный режим»; плюс ~1860 ₽ за 50% ядра.
- Selectel: 6087 ₽ по калькулятору — почти половина это платный резерв IOPS
  диска, плюс отдельно роутер и IP; S3 по умолчанию в Казахстане.
- Timeweb: 1780 ₽, один провайдер Terraform, Москва без очереди.
Независимое сравнение Tproger на одинаковой конфигурации даёт тот же порядок.

**4. Файлы пользователей (60 с).** Раньше в БД лежали вечные публичные URL.
Теперь в БД ключ объекта, а `/api/files/<key>` на каждый запрос отдаёт 302 на
подписанную ссылку на 5 минут; бакет приватный (ADR 0002). Фронтенд не
менялся. По ходу нашёл и исправил два бага: ссылки подписывались внутренним
адресом `minio:9000`, и миграция оставляла имя бакета в ключе — сломала бы
все старые файлы.

**5. CI/CD (40 с).** Тег → lint → сборка трёх образов в GHCR с тегом SHA →
тесты и smoke-проверка образов → деплой по SSH. На сервер уходит ровно тот
образ, который прошёл тесты (ADR 0004). Нашёл баг: шаги с `secrets` в `if:`
уронили бы первый же деплой.

**6. Что сознательно не сделано (30 с).** Бэкапов вне сервера нет — скрипты
готовы, нужен бакет. Файлы на том же диске (ADR 0003). Это осознанный
компромисс ради цены и срока, записанный в ADR, а не забытое.

## 2. Вероятные вопросы

**Что будет, если ВМ умрёт?**
Данные потеряются: Postgres и файлы на одном диске. Это зафиксировано в
ADR 0003. Перед защитой снят дамп вручную. Путь исправления готов:
`pg_backup.sh` + systemd-таймер, нужен только бакет вне сервера.

**Почему не Kubernetes / managed Postgres?**
Один сервис, учебная нагрузка, бюджет ~1800 ₽. Kubernetes добавил бы
стоимость control plane и сложность без выигрыша. Managed Postgres — отдельный
счёт; для демо достаточно контейнера с томом.

**Как выполняется 242-ФЗ?**
Персональные данные (БД и файлы) физически в Москве. За границей только
инфраструктурный трафик: GitHub Actions, GHCR, Let's Encrypt, Web Push — это
не хранение данных пользователей.

**А если GitHub/GHCR заблокируют?**
Риск описан в ADR 0004 (прецедент Docker Hub 2024). Путь отхода: реестр в РФ —
замена префикса образов, compose уже читает его из `IMAGE_REGISTRY`; CI можно
перенести, крайний вариант — ручная сборка и деплой по SSH.

**Почему presigned redirect, а не просто ссылка в JSON?**
Ссылка с TTL протухла бы в открытой вкладке и в старых сообщениях чата.
Стабильный путь, который перевыпускает подпись, этих проблем не имеет.

**`/api/files` без авторизации — это дыра?**
Не хуже, чем было (раньше бакет был публичным), но и не идеально: кто знает
ключ, получит файл. Ключи новых файлов содержат UUID. Проверка участия во
встрече — следующая задача.

**Почему state Terraform локальный?**
Terraform запускает один человек; удалённый backend — ещё один платный бакет и
ключи. Риск потери файла закрыт ручной копией.

**Как защищён сервер?**
Облачный файрвол: SSH только с моего IP, наружу 80/443. Внутри ufw, fail2ban,
вход только по ключу, root запрещён, автообновления безопасности без
авто-перезагрузки. В Terraform `prevent_destroy` на сервере.

**Почему MinIO на том же сервере?**
Цена и сроки (ADR 0003). Код от этого не зависит: переход на S3 провайдера —
замена переменных в `.env.prod`.

**Сколько стоит?**
~1780 ₽/мес, почасовая оплата. Выключенный сервер тоже оплачивается, поэтому
сервер создаётся ближе к защите.

## 3. Сценарий демо (5 минут)

1. `https://bimeet.pro` — лендинг; замок в адресной строке (Let's Encrypt).
2. `https://app.bimeet.pro` — вход по коду, создать встречу.
3. Загрузить аватар → DevTools → Network: `/api/files/...` → **302** →
   `s3.bimeet.pro/...X-Amz-Signature=...` → картинка.
4. Скопировать прямой URL объекта без подписи → **403** (бакет приватный).
5. Терминал: `cd infra/terraform && terraform plan` → «No changes» (код =
   реальность).
6. GitHub → Actions → последний деплой: lint → build → test → deploy.
7. По желанию: `ssh deploy@<ip> docker compose ps`.

**Подготовить заранее:** открытые вкладки, залогиненный пользователь, тестовая
встреча; дамп БД на ноутбуке; на случай отказа сети — скриншоты шагов 3–6.

## 4. Перед защитой (чек-лист)

- [ ] За 5–7 дней: баланс, `terraform apply`, `.env.prod`, A-записи, секреты,
      тег, проверка по `docs/runbooks/timeweb-launch.md`.
- [ ] В `.env.prod` стоит `AUTH_TEST=true`: код входа для всех `120401`
      (константа `testLoginCode` в `backend/internal/service/auth/service.go`).
      Выключить после защиты.
- [ ] `admin_cidrs` = IP той сети, откуда будешь на защите (иначе SSH не пустит).
- [ ] Дамп БД снят и скопирован на ноутбук.
- [ ] Прогнать демо целиком один раз.

**Вход по коду.** Логин работает через письмо с кодом. На защите включён
`AUTH_TEST=true`: письма не отправляются, код для любого email — `120401`.
Если спросят: это осознанный демо-режим (почтовый провайдер не подключён),
в нём войти может кто угодно, поэтому он выключается сразу после защиты.
Для реальных писем нужен ключ Resend и подтверждённый домен.
