# Bimeet: переход инфраструктуры на Timeweb Cloud — материал для ВКР

Дата сводки: 2026-11-18. Все изменения смержены в `master` репозитория
`AntonSlavshchikov/bimeet` через PR #7 (merge-коммит `efcebc2`, 2026-11-18).
Первичные документы в репозитории: `docs/adr/0001…0004`, `docs/architecture.md`,
`infra/terraform/README.md`, `docs/runbooks/timeweb-launch.md`, `docs/deploy.md`.

Правило для текста ВКР: цифры и факты ниже проверены; помеченное «не проверено»

## 1. Что изменилось (кратко)

- **Хостинг:** выбран Timeweb Cloud (Москва) вместо рассматривавшихся Yandex
  Cloud и Selectel. Инфраструктура описана в Terraform заново.
- **Хранение файлов:** вместо публичного бакета с вечными URL — приватный бакет,
  ключи объектов в БД и выдача через presigned-редирект `/api/files/{key}`.
- **Объектное хранилище:** MinIO на той же ВМ (без платного S3 провайдера).
- **CI/CD:** GitHub Actions + GHCR остаются; деплой по git-тегу через SSH.
- **Статус развёртывания:** код готов и смержен, `terraform plan` против
  реального API прошёл; `terraform apply` (создание сервера) намеренно отложен
  до периода перед защитой ради экономии.

## 2. Выбор провайдера

### Критерии (decision drivers)
1. Хранение персональных данных граждан РФ на территории РФ (242-ФЗ).
2. Наличие Terraform-провайдера (инфраструктура как код).
3. Цена для учебного проекта.
4. Регион Москва, отсутствие очереди на ресурсы.

### Сравнение (цены за месяц, с НДС)

| Провайдер | Цена | Конфигурация | Источник |
|---|---|---|---|
| Timeweb Cloud | **1780 ₽** (ВМ 1580 ₽ + IPv4 200 ₽), почасовая оплата | 1 CPU 3.3 ГГц / 2 ГБ / 15 ГБ NVMe, Москва `ru-3`/`msk-1` | панель Timeweb Cloud, 2026-11-16 |
| Yandex Cloud | **≈1860 ₽** (оценка) | пакет 2 vCPU с долей ядра 50% / 2 ГБ, IP включён (1659 ₽) + 15 ГБ сетевого SSD по 13–14 ₽/ГБ | публичные страницы Yandex Cloud, 2026-11-17; калькулятор не использовался |
| Selectel | **6087,61 ₽** | Standard, 2 vCPU / 4 ГБ, SSD «Универсальный v2» 20 ГБ | калькулятор панели Selectel, 2026-11-17 |

Разбивка Selectel: vCPU 1470,38 + RAM 1069,36 + диск 209,68 + **резерв 11 000 IOPS
2948,62** + публичный IP 189,57 + облачный роутер 200 = 6087,61 ₽. Почти
половина — платный резерв производительности диска.

Независимое сравнение на одинаковой конфигурации (2 vCPU, 4 ГБ, 40 ГБ NVMe,
Ubuntu 24.04, IPv4, Москва) — Турчак В., Tproger, 30.10.2026: Timeweb Cloud
3000 ₽ (трафик бесплатный и безлимитный), Selectel 3230,91 ₽ (`ru-7a`, Standard;
3 ТБ трафика бесплатно, далее 0,8962 ₽/ГБ), Yandex Cloud ≈3449,89 ₽. Порядок
совпадает с собственным сравнением.

### Почему не Yandex Cloud
- **Физический риск, реализовавшийся в октябре 2026:** за четыре дня атаками
  беспилотников выведены из строя три дата-центра Яндекса: Сасово, Рязанская
  обл. (7–8 окт., остановлен полностью; зона `ru-central1-b`), Калуга (9 окт.,
  частично), Владимир (10–11 окт., остановлен полностью; зона `ru-central1-a`).
  Официальное сообщение Yandex Cloud: «Оставшуюся конфигурацию ресурсов считаем
  неустойчивой. Режим работы платформы является аварийным»; клиентам рекомендованы
  собственные планы аварийного восстановления. Затронуты сервисы клиентов
  (Додо Пицца, Lamoda, ГИС «ВетИС»). Управление квотами переведено в ручной
  режим. Yandex Cloud договорилась с Selectel, K2Cloud и VK Cloud об ускоренном
  переносе клиентов. Сообщения о приостановке ресурсов для новых клиентов шли
  от анонимного источника и были опровергнуты Яндексом — подавать именно так.
- **Цена:** ≈1860 ₽ за 50% ядра против 1780 ₽ за полное ядро у Timeweb.
- **Доверие:** субъективная оценка автора.

### Почему не Selectel
- Регион `ru-9`, заложенный изначально, — Санкт-Петербург, примерно вдвое
  дороже московского `ru-6`; дешёвые Shared-конфигурации в Москве только в
  `ru-2c`/`ru-7a`, `ru-2` помечен «ёмкость ограничена».
- Отдельная оплата роутера (200 ₽), IP (189,57 ₽) и резерва IOPS диска.
- Форма создания S3-бакета по умолчанию предлагает `kz-1` (Алматы), что
  противоречит критерию «данные в РФ».
- Сложность: три Terraform-провайдера (selectel, openstack, aws), сервис-
  пользователи, сеть, роутер. Эта версия была полностью написана и осталась в
  истории репозитория, затем заменена.

## 3. Итоговая архитектура (Timeweb)

Одна ВМ Timeweb Cloud (Москва, `msk-1`, Ubuntu 24.04, 1 CPU / 2 ГБ / 15 ГБ NVMe),
на ней один `docker-compose.prod.yml` в общей сети:
- **Traefik v3** — единственная точка входа (80→443), TLS от Let's Encrypt;
- **landing** — статический Next.js в nginx (`bimeet.pro`, `www`);
- **frontend** — React SPA в nginx (`app.bimeet.pro`), nginx проксирует `/api/*`
  в backend (backend наружу не публикуется);
- **backend** — Go (handler → service → repository → PostgreSQL);
- **PostgreSQL 16** и **MinIO** — в Docker-томах на диске той же ВМ;
- MinIO доступен браузеру как `s3.bimeet.pro` только по подписанным ссылкам.

DNS домена `bimeet.pro` у регистратора reg.ru, вне Terraform: A-записи `@`,
`www`, `app`, `s3` → IP сервера.

Готовые диаграммы Mermaid для иллюстраций — `docs/architecture.md`:
(1) контейнеры на ВМ, (2) конвейер деплоя, (3) sequence загрузки/выдачи файла,
(4) ресурсы Terraform.

## 4. Инфраструктура как код (Terraform)

- Провайдер `timeweb-cloud/timeweb-cloud` 1.8.4; схема ресурсов взята из самого
  провайдера (`terraform providers schema`).
- **12 ресурсов:** проект, SSH-ключ, floating IP, сервер, облачный файрвол и
  7 правил (SSH 22 только с IP администратора; 80/443 и ICMP — всем; исходящий
  tcp/udp/icmp).
- Floating IP создаётся **до** сервера и передаётся через `floating_ip_id`:
  cloud-init при первой загрузке ставит Docker и нуждается в интернете сразу.
- cloud-init: пользователь `deploy`, вход только по ключу, root запрещён,
  Docker + compose из официального репозитория, ufw, fail2ban, автообновления
  безопасности без авто-перезагрузки, chrony, swap 2 ГБ, ротация логов Docker.
- `prevent_destroy` на сервере (диск хранит БД и файлы),
  `ignore_changes = [cloud_init, os_id]`.
- State — локальный файл (один оператор; удалённый backend = лишний платный
  бакет). DNS — вне Terraform.
- Проверено: `terraform fmt`, `validate`, tflint (также в CI на каждый PR);
  `terraform plan` против реального API: 12 на создание, 0 изменений/удалений;
  через API подтверждено: `ru-3` = Москва (зона `msk-1`), конфигуратор 31 =
  NVMe 3.3 ГГц, образ 99 = Ubuntu 24.04.

## 5. Хранение файлов: приватный бакет + presigned redirect

- Было: в БД полный публичный URL, бакет публичный (вечные ссылки, привязка к
  домену и хранилищу).
- Стало: миграция `026_file_keys` переименовывает колонки в `*_key` и
  превращает URL в ключи; API отдаёт стабильный путь `/api/files/<key>`,
  который на каждый запрос отвечает **302** на presigned GET со сроком
  5 минут (`S3_PRESIGN_TTL`). Фронтенд не менялся (JSON-поля прежние).
- Бакет MinIO приватный: `minio-init` выполняет `mc anonymous set none`.
  Проверено на реальном MinIO: анонимный GET → **403**, presigned GET → **200**.
- Найденные и исправленные дефекты:
  1. presigned-ссылки подписывались внутренним адресом `http://minio:9000`,
     недоступным из браузера → отдельный клиент на `S3_PRESIGN_ENDPOINT`
     (публичный `https://s3.bimeet.pro`) + регрессионный тест;
  2. миграция оставляла имя бакета в ключе (`avatars/avatars/<id>.png` вместо
     `avatars/<id>.png`) — все старые файлы стали бы недоступны → регулярное
     выражение `^https?://.*/((avatars|chat|receipts)/)`, проверено Go-тестом и
     запуском в PostgreSQL 16.
- Почему переменные называются `AWS_*`: backend использует AWS SDK как
  стандартный клиент S3-протокола; запросы идут в собственный MinIO, это задаёт
  `S3_ENDPOINT`.

## 6. CI/CD

`.github/workflows/deploy.yml`, запуск по push git-тега:
lint (Go `make lint vet`, `npm run lint`) → build (три образа в GHCR, тег = SHA
коммита) → test (юнит-тесты Go и фронтенда, smoke-проверка собранных образов)
→ deploy (окружение `prod`: `scp` compose-файла, по SSH
`docker compose pull && up -d` с тегом проверенного коммита).
На сервер уходит ровно протестированный образ.
Найден и устранён дефект: шаги пуша в реестр Selectel использовали контекст
`secrets` в условии `if:` шага, что GitHub Actions не допускает — первый же
тег уронил бы деплой.
Риск: зависимость от зарубежных GitHub Actions/GHCR (не данные пользователей);
путь отхода — российский реестр образов (префикс образов задаётся переменной
`IMAGE_REGISTRY`), перенос CI; совместимость GitVerse с Actions не проверялась.

## 7. Безопасность

Облачный файрвол (SSH только с IP администратора), ufw внутри ВМ, fail2ban,
вход только по ключу, root запрещён, отдельный SSH-ключ для CI, секреты только в
`.env.prod` на сервере (chmod 600) и в GitHub Secrets; Terraform-токен в
git-игнорируемом `terraform.tfvars`. Чаты шифруются на диске (AES-256,
`CHAT_ENCRYPTION_KEY`).

На время защиты включён демо-режим входа `AUTH_TEST=true`: письма не
отправляются, код единый (почтовый провайдер не подключён). В этом режиме
войти под любым email может кто угодно, поэтому список администраторов
оставлен пустым, а режим выключается после защиты.

## 8. Соответствие 242-ФЗ

Персональные данные (PostgreSQL и файлы MinIO) физически в Москве. За пределы
РФ выходит только инфраструктурный трафик: GitHub Actions/GHCR (сборка и образы),
Let's Encrypt (выпуск сертификата), Web Push (доставка уведомлений через
сервисы браузеров) — это не хранение данных пользователей.

## 9. Ограничения (осознанные компромиссы)

- Нет резервного копирования вне сервера: БД и файлы на одном диске одной ВМ.
  Скрипты бэкапа готовы (`infra/backup/`: pg_dump → S3, systemd-таймер,
  восстановление во временную БД), но требуют бакета вне сервера. Перед
  защитой дамп снимается вручную.
- MinIO делит 15 ГБ диска и 2 ГБ RAM с остальными сервисами — достаточно для
  демонстрации, не для реальной нагрузки.
- Нет мониторинга заполнения диска.
- `/api/files/*` без авторизации: кто знает ключ, получит файл (ключи новых
  файлов содержат UUID).
- Выключенный сервер Timeweb тарифицируется, поэтому экономия достигается
  созданием сервера незадолго до защиты (проверка автора, 2026-11-17).
- Не проверено: цена Selectel Shared Line с минимальным IOPS.
