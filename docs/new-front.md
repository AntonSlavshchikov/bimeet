# Редизайн Bimeet под Warm Canvas

## 1. Цель и критерии готовности

Полностью привести frontend Bimeet к варианту `01 · Warm Canvas` из `design/new-front.html`. Источником истины считать именно макеты приложения «Список», «Детали», «Телефон» и рекомендованный вариант навигации встречи `Quiet Rail`; презентационную оболочку с переключателем вариантов в приложение не переносить.

Редизайн охватывает все пользовательские и служебные страницы frontend. Backend, API, DTO, бизнес-логика и маршруты не меняются.

Готовый интерфейс должен:

- повторять палитру, типографику, плотность, радиусы, сетку и расположение блоков Warm Canvas;
- использовать трёхколоночную desktop-компоновку `220px / main / 276px`;
- переходить в двухколоночный режим без правого rail при ширине до `1080px`;
- переходить в мобильную оболочку с верхней и нижней навигацией при ширине до `760px`;
- сохранять все существующие функции, включая публичные встречи, админку, профиль, уведомления и все разделы встречи;
- использовать градиент только для основных CTA и важных активных состояний;
- использовать плотные непрозрачные поверхности без декоративного glassmorphism;
- сохранить тёмную тему как адаптацию Warm Canvas с той же геометрией;
- не создавать горизонтальную прокрутку при ширине от `320px`;
- пройти существующие `lint`, `build` и 40 тестов, а также новые UI-проверки.

Текущее исходное состояние исправно: `npm run lint`, `npm run build` и `npm run test` проходят.

## 2. Дизайн-система Warm Canvas

### Глобальные токены

Пересобрать глобальную тему в `frontend/src/index.css` вокруг точных значений макета:

- `ink: #121214`;
- `ink-2: #5e5a55`;
- `ink-3: #9a948d`;
- `paper: #faf8f2`;
- `surface: #ffffff`;
- `surface-2: #f3f0e9`;
- `line: rgba(18,18,20,.09)`;
- `line-strong: rgba(18,18,20,.15)`;
- `brand-a: #fb7185`;
- `brand-b: #a78bfa`;
- `brand-c: #38bdf8`;
- `success: #299764`;
- `warning: #d97706`;
- `danger: #dc5a62`;
- `purple: #7857c8`.

Удалить несогласованные iOS-цвета и недействующие ссылки на `--color-brand-rose`, `--color-brand-violet`, `--color-brand-sky`. Все градиенты должны использовать единые `brand-a/b/c`.

Определить отсутствующие сейчас глобальные utilities (`warm-canvas-bg`, `warm-surface-shadow`) либо удалить их в пользу семантических классов. В репозитории не должно остаться классов или CSS-переменных без определения.

### Геометрия и поверхности

Зафиксировать единую шкалу:

- навигационные элементы: `10px`;
- контролы: `12px`;
- панели и списки: `18px`;
- оболочка приложения: `30px`;
- компактные badges: полный pill-radius;
- поля и кнопки: высота `36px`;
- мобильные action-кнопки: `32px`;
- основной desktop shell — единственный элемент с заметной тенью `0 24px 70px rgba(36,30,20,.11)`.

Контентные карточки, формы, rail, dropdown, auth-карточки и панели встречи сделать непрозрачными. Удалить blur из `AuthShell`, формы и декоративных карточек. Оставить лёгкую полупрозрачность и blur только у мобильной верхней и нижней системной навигации, где это присутствует в эталоне.

### Типографика

- Основной шрифт — `Inter`.
- Убрать отдельный Quicksand-стиль wordmark; название `bimeet` выводить Inter с весом около `760`.
- Заголовок страницы desktop: `28px`, `line-height: 1.05`, `letter-spacing: -0.035em`.
- Заголовок страницы mobile: `31px`, на экранах до `420px` — `27px`.
- Заголовок встречи: `26px`.
- Название события в строке: `12.5px / 700–720`.
- Основной текст: `13–15px`.
- Метаинформация: `9–11.5px`.
- Секционные подписи: uppercase, `9–10px`, tracking `0.08–0.11em`.
- Для дат, времени, счётчиков и процентов сохранить tabular numerics.

### Базовые компоненты

Привести общие UI-компоненты к одному контракту:

- `Button`: основной вариант с градиентом `115deg`; soft на `surface-2`; outline с тонкой линией; ghost без собственной поверхности; danger на семантическом красном.
- `Input`, `Textarea`, `Select`, `SearchInput`: высота `36px`, radius `12px`, спокойный `surface-2`, единый focus ring.
- `SegmentedControl`: фон `surface-2`, padding `3px`, активный сегмент белый с минимальной тенью.
- `ListGroup`: radius `18px`, белый фон, общая внешняя граница и разделители между строками.
- `StatusPill`: фон как 10% оттенок статуса, компактная типографика `9–10px`.
- `Avatar`: сохранить цветные градиенты, привести размеры и обводку к макету.
- `RailCard`: radius `18px`, padding `16px`, без собственной тяжёлой тени.
- `Dropdown`, `Popover`, `Dialog`, `Toast`: те же поверхности, линии, радиусы и типографика; фон overlay без декоративного blur.
- `MiniCalendar` и `DateRangePicker`: активная дата на градиенте `brand-b → brand-c`, остальные состояния нейтральные.
- Удалить `GooeyTabs`; если `framer-motion` больше нигде не используется, удалить зависимость.

Обновить страницу дизайн-системы: показать light/dark, все состояния кнопок, полей, статусов, списков, rail, календаря, Quiet Rail, диалогов, пустых состояний и адаптивных строк событий.

## 3. Оболочка и навигация

### Desktop ≥1081px

Перестроить Layout в точном соответствии с макетом:

- внешний фон — кремовый холст с очень сдержанными radial-акцентами по краям;
- shell — `width: min(1320px, 100%)`, высота в пределах viewport, radius `30px`;
- сетка shell: `220px minmax(0,1fr) 276px`;
- sidebar: `22px 14px 15px`, правая граница;
- main: `25px 26px 36px`;
- right rail: `25px 20px`, левая граница;
- каждая колонка прокручивается независимо, shell остаётся неподвижным;
- right rail показывается только там, где передан контент страницы.

Sidebar привести к макету:

- логотип и wordmark сверху;
- секция «Навигация»: «Все встречи», «Мои встречи», «Уведомления», «Админка» для администратора;
- секция «Фильтры»: «Иду», «Организую», «Прошедшие»;
- активный пункт — `surface-2`, тёмный текст, без яркого фона;
- счётчики — нейтральные серые pills; только непрочитанные уведомления могут использовать брендовый акцент;
- профиль пользователя закрепить снизу в отдельной панели `surface-2`.

### Tablet 761–1080px

- Сетка `200px minmax(0,1fr)`.
- Right rail полностью скрывается.
- Строка события сокращается: убрать отдельный столбец количества участников, сохранить дату, название, время, аватары, статус и chevron.
- Все действия остаются доступны через main и sidebar.

### Mobile ≤760px

Заменить текущий центрированный navbar с иконкой календаря:

- верхняя панель высотой `54px`;
- слева знак и wordmark `bimeet`;
- справа кнопки поиска и создания встречи;
- заголовок страницы переносится в контент;
- main получает горизонтальные отступы `14px`, нижний запас не менее `78px`;
- нижняя навигация содержит три визуальных пункта как в макете: «Встречи», «Уведомления», «Профиль»;
- публичные встречи и админка остаются доступны через компактное навигационное меню, открываемое по brand-кнопке, не добавляя постоянные пункты в bottom nav;
- учитывать `safe-area-inset-bottom`;
- на ширине до `420px`: внешний отступ `6–10px`, shell radius `27px`, контентные отступы `10px`.

## 4. Основные продуктовые экраны

### Список встреч

Сохранить текущую группировку и данные, но довести экран до пиксельной структуры эталона:

- desktop toolbar: растянутый поиск, кнопка уведомлений, градиентная кнопка «Создать»;
- отступ до заголовка `28px`;
- заголовок и подзаголовок слева, фильтр `Все / Иду / Организую / Архив` справа;
- группы «Сегодня» и месяцы с uppercase-подписями и количеством справа;
- строки объединены в цельную белую поверхность;
- desktop grid строки: `47px minmax(150px,1fr) 92px 64px 48px 72px 12px`;
- цветная полоса слева: `4px`, отступ сверху/снизу `10px`;
- дата крупная, подпись месяца/дня недели маленькая uppercase;
- название, место, время, стек аватаров, количество, статус и chevron выровнены как в макете;
- hover меняет только нейтральный фон;
- завершённые события приглушаются, но остаются читаемыми;
- на mobile остаются дата, название, статус и chevron; на ширине до `420px` статус скрывается.

Right rail:

- карточка «Сегодня» или «Ближайшие» с большой датой и ближайшими событиями;
- отдельный мини-календарь;
- карточка «Этот месяц» с четырьмя показателями;
- четвёртый показатель формировать из существующих непрочитанных уведомлений/ответов вместо текущей заглушки `—`;
- все расчёты выполнять на существующих клиентских данных, без нового API.

Публичный каталог перевести на тот же шаблон заголовка, поиска, секционных labels и строк. Сохранить деление на ближайшие/остальные, расстояния и inline-действие присоединения.

### Детали встречи

Использовать выбранный вариант `Quiet Rail`.

Верх detail-страницы:

- topbar «Ко всем встречам» слева и меню действий справа;
- убрать отдельную цветную полосу события и зависящий от `eventAccentColor` blur;
- hero-панель: status badge, заголовок, описание, дата/время, место, участники;
- справа сверху — очень слабое радиальное бренд-пятно без blur поверхности;
- CTA участия: градиентная «Я иду» и нейтральная «Не смогу»;
- organizer actions сохраняются в overflow-menu;
- завершённая встреча получает спокойный warning-banner.

Блок разделов:

- единая панель radius `18px`;
- верхняя строка: label «Разделы встречи» и действие «Завершить» для организатора;
- ниже — равномерный ряд иконок Quiet Rail на фоне `surface-2`;
- активный раздел — белая поверхность, тёмная иконка, минимальная тень;
- кнопки имеют `aria-label`, `aria-selected`/`aria-pressed`, tooltip и видимый focus;
- непрочитанный чат показывает компактный badge;
- разделы: участники, сборы, опросы, вещи, попутчики, чат и условная история изменений;
- активный раздел продолжает поддерживать `?tab=...` для прямых ссылок;
- содержимое раздела располагается под Quiet Rail без дополнительной вложенной «карточки в карточке».

Привести содержимое feature-разделов к макету:

- опросы — заголовок/число голосов, спокойные строки и градиентные progress bars;
- вещи — компактный разделённый список с зелёными отметками и inline-действиями;
- участники — аватар, имя, роль, статус справа;
- сборы — цельные панели, прогресс и действия без разношёрстных вложенных рамок;
- попутчики — компактные строки водителей и мест, а не крупные самостоятельные карточки;
- чат — нейтральные входящие сообщения и брендовые исходящие, единый composer;
- история — разделённый список изменений с компактными old/new badges;
- пустые состояния всех разделов используют один общий компонент.

### Формы

Экран создания/редактирования:

- desktop-ширина контента около `720px`;
- заголовок, подзаголовок и back-link выровнять по стандартной page-head;
- секции формы — белые плотные панели radius `18px`;
- radio cards, календарь, location picker, поля и textarea привести к общей геометрии;
- sticky action bar сделать непрозрачной, без blur, с тонкой верхней линией;
- на mobile действия фиксировать над bottom nav и safe area;
- не менять payload, валидацию и мутации.

### Остальные страницы

- Уведомления: цельный list-group, непрочитанная строка отличается только мягким акцентом; desktop actions в заголовке, mobile actions в navbar.
- Профиль: desktop grid `280px / main`; слева карточка пользователя, справа редактирование/статистика; controls и stats используют общую систему.
- Админка: те же page-head, сегменты и панели; заменить hardcoded `#007AFF`, белые tooltip и iOS-палитру графиков на Warm Canvas tokens, включая dark mode.
- Login/invite: кремовый canvas с сдержанными brand-пятнами, плотная белая карточка без blur, логотип и типографика Warm Canvas.
- Location picker/map: линии и радиусы дизайн-системы, согласованные empty/loading/error states.
- Push settings и notification popover: уменьшить визуальную вложенность, привести к общим панелям.
- `_design-system`: использовать как полный визуальный стенд нового интерфейса.

## 5. Интерфейсы и внутренняя структура

Публичные backend-интерфейсы, API-запросы и модели событий не меняются.

Внутри frontend:

- сохранить `Layout` с `rail` и `mobileActions`, но перенести вычисление сетки и breakpoint-правила в централизованные shell-классы;
- создать общий `PageHeader` для заголовка, подзаголовка, фильтров и действий;
- создать общий `EmptyState`;
- создать `EventSectionNav` для Quiet Rail с интерфейсом `value`, `onChange`, `options`, `action`;
- `options` содержит ключ, локализованную подпись, иконку и необязательный badge;
- удалить `GooeyTabs` после миграции detail-страницы;
- сохранить `EventListRow`, но оформить desktop/tablet/mobile layouts через централизованные responsive-классы;
- не переносить презентационные классы `br-*`, `app-*` напрямую: реализовать их семантику через существующие shared/widgets/pages слои;
- все новые видимые строки синхронно добавить в `ru.json` и `en.json`;
- не дублировать query keys и не менять TanStack Query invalidation.

## 6. Порядок реализации

1. Зафиксировать контрольные изображения текущих страниц и эталона при `1440×900`, `1080×900`, `760×900`, `390×844`, light/dark.
2. Исправить токены, отсутствующие utilities, градиенты, семантические цвета и общие primitives.
3. Перестроить Layout, sidebar, right rail, mobile topbar и bottom nav.
4. Довести список встреч, публичный каталог и `EventListRow` до эталонной сетки.
5. Перестроить detail hero и внедрить Quiet Rail.
6. Последовательно обновить все feature-разделы встречи.
7. Обновить формы, уведомления, профиль, админку, auth/invite и вспомогательные интерфейсы.
8. Обновить дизайн-систему и удалить устаревшие компоненты/зависимости.
9. Провести responsive, dark-mode, accessibility и visual parity аудит.
10. После изменения кода выполнить `graphify update .`.

Каждый этап должен завершаться рабочей сборкой; нельзя сначала удалить старые primitives, пока на них остаются потребители.

## 7. Проверка и приёмка

Автоматические проверки:

- `npm run lint`;
- `npm run build`;
- `npm run test`;
- тест структуры `EventSectionNav`: переключение, ARIA-состояния, keyboard focus, badge;
- тест синхронизации detail-раздела с query parameter;
- тест responsive visibility навигации через DOM-классы;
- тест отсутствия неопределённых brand CSS variables;
- существующие тесты группировки, API, темы и авторизации остаются зелёными.

Ручные сценарии:

- desktop с rail, desktop без rail, tablet и mobile;
- пустой список, один event, длинный список, длинные названия/адреса;
- все статусы: организатор, идёт, приглашён, отказался, завершено, мест нет;
- создание и редактирование события;
- переключение всех Quiet Rail-разделов;
- действия участника и организатора;
- пустые и заполненные опросы, сборы, вещи, попутчики и чат;
- уведомления, профиль, public catalog и admin;
- русский и английский языки;
- light и dark темы;
- keyboard-only навигация, focus rings, reduced motion;
- iPhone safe areas и отсутствие перекрытия bottom nav.

Визуальные допуски:

- ключевые размеры, отступы и ширины колонок должны совпадать с макетом;
- допустима адаптация контента под реальные данные;
- нельзя возвращать тяжёлые тени, случайные яркие цвета, стеклянные панели или крупные самостоятельные карточки там, где макет использует цельный список;
- градиент применяется только к главным CTA, выбранным датам и специально обозначенным активным состояниям.

## 8. Зафиксированные решения и допущения

- Применяется Warm Canvas, а не Liquid Workspace или Pocket Moments.
- Для разделов встречи применяется Quiet Rail.
- Тёмная тема сохраняется и адаптируется.
- Редизайн охватывает весь `frontend`, а не только список и detail.
- Backend и данные не изменяются.
- Все существующие маршруты и функции сохраняются.
- Маркетинговая оболочка макета и лаборатория трёх вариантов не переносятся в приложение.
- Light theme является визуальным эталоном; dark theme повторяет её структуру на отдельных семантических токенах.
- Новый постоянный пункт мобильной навигации не добавляется: дополнительные маршруты доступны через скрываемое меню.
