# Безопасная выдача invite token и платёжных чеков

## Цель

Закрыть первые две High-находки из `docs/errors.md`, сохранив текущий пользовательский сценарий:

- invite token доступен только организатору события;
- организатор видит чеки всех участников;
- участник видит только собственный чек;
- остальные участники не получают URL чужих чеков.

## Граница исправления

Фильтрация выполняется в `event.Service.GetByID` после проверки доступа к событию и до передачи `EventDetail` в HTTP handler. Это централизованная граница participant-facing API и минимальное изменение существующей архитектуры `handler -> service -> repository`.

Repository продолжает собирать полный `EventDetail`, необходимый организатору. Service определяет роль вызывающего по `detail.Organizer.IsMe` и принадлежность взноса по `contribution.User.IsMe`:

- для организатора ответ не изменяется;
- для участника `InviteToken` удаляется;
- для участника `ReceiptURL` удаляется у каждого чужого взноса и сохраняется у собственного.

Поле `EventDetail.InviteToken` становится опциональным, чтобы при JSON-сериализации оно отсутствовало, а не возвращалось как нулевой UUID. Frontend-тип также становится опциональным; кнопка копирования ссылки остаётся organizer-only и использует токен только при его наличии.

## Совместимость

Существующие organizer-сценарии сохраняются: копирование invite link и просмотр всех pending receipts продолжают работать. Участник сохраняет возможность получить URL собственного загруженного чека. Структура остальных данных события и HTTP-коды не меняются.

## Проверка

Regression-тесты service-слоя должны сначала воспроизвести утечки, затем подтвердить:

1. организатор получает invite token и все receipt URL;
2. участник не получает invite token;
3. участник получает собственный receipt URL;
4. участник не получает receipt URL другого пользователя.

Handler-тест дополнительно проверяет фактическую JSON-форму participant response: ключ `invite_token` отсутствует, собственный `receipt_url` присутствует, чужой отсутствует.

После реализации выполняются focused-тесты event service/handler, `go test ./...`, `go vet ./...`, frontend build и `graphify update .`.
